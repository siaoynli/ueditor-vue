# M0 详细计划：脚手架 + 金标准对照 Harness + 语料库管线

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立 pnpm monorepo 工程底座与"金标准对照"测试基建，使后续每个里程碑的保真验收（新旧双栏 HTML diff）可自动执行。

**Architecture:** playground 用自定义 Vite 插件在**内存中**按 `_examples/editor_api.js` 清单拼接原版 `_src` 为 baseline bundle（只读源码目录，不落盘产物）；diff 由 `normalizeHtml` 归一化后字符串比对；语料以 manifest + 静态 fixture 驱动 Playwright 生成基线快照。

**Tech Stack:** pnpm workspace · Vite 5 · Vitest · Playwright · TypeScript。

**Spec:** `docs/superpowers/specs/2026-11-03-ueditor-vue-design.md`；上位计划 `docs/superpowers/plans/2026-11-03-ueditor-vue-master-plan.md`（本计划覆盖其步骤 1–3）。

## Global Constraints

- 直接依赖总数（全仓库生产包合计）≤4；开发依赖不受限
- `ueditor-dev-1.5.0/` 只读：任何任务不得在该目录内写文件（内存拼接/静态 serve 合规）
- 注释中文；标识符英文
- 分支 `feat/m0-harness`，从 `feat/design-spec`（含规格与总计划文档）切出；本计划完成后 PR 目标 `feat/design-spec`
- `.gitignore` 追加 `.superpowers/` 与 `node_modules/`、`dist/`
- 每任务结束跑 `pnpm -r test` 与 `pnpm lint` 绿后提交，提交信息含 `Co-Authored-By: Claude <noreply@anthropic.com>`

## Review Focus（规格隐含、各任务测试未必全覆盖）

1. **baseline 拼接顺序漂移**：拼接清单若与 `Gruntfile.js:66-75` 实际语义不符，基线行为静默失真 → Task 3 用"拼接结果含 `UE.Editor` 且 `queryCommandState('bold')` 可用"钉死。
2. **normalizeHtml 过度清洗**：归一化掉真实差异会让金标准假绿 → Task 2 测试显式断言"粗细体差异必须报 diff"。
3. **`ueditor-dev-1.5.0` 静态路径泄漏**：baseline serve 只允许 dev server，禁止进入 `pnpm -r build` 产物 → Task 5 构建后 grep 产物无 `ueditor-dev`。
4. **paste 仿真边界**：M0 基线走 `setContent`+命令，不经 paste 链（paste 仿真工具归 M2）→ Task 4 manifest 字段 `channel` 显式标注 `"setContent"`，杜绝误当粘贴基线。
5. **workspace 版本漂移**：所有包共享根 `pnpm-workspace.yaml` catalog 版本 → Task 1 锁定 vite/vitest/typescript 单源版本。

### Task 2: `normalizeHtml` 归一化工具（TDD）

**Files:**
- Create: `packages/test-utils/src/normalizeHtml.ts`、`packages/test-utils/src/normalizeHtml.spec.ts`

**Interfaces:**
- Consumes: Task 1 的 test-utils 包与 vitest
- Produces: `normalizeHtml(html: string, opts?: { stripAttrs?: string[] }): string`（后续 Task 3/4 及 M2 命令矩阵共用；stripAttrs 默认 `[]`）

- [ ] **Step 1: 写失败测试**

```ts
import { describe, it, expect } from 'vitest';
import { normalizeHtml } from './normalizeHtml';

describe('normalizeHtml', () => {
  it('属性顺序不影响结果', () => {
    expect(normalizeHtml('<p class="a" id="b">x</p>'))
      .toBe(normalizeHtml('<p id="b" class="a">x</p>'));
  });
  it('标签间空白折叠，但加粗差异必须保留（Review Focus 2）', () => {
    const a = normalizeHtml('<div>\n  <p>文本</p>\n</div>');
    const b = normalizeHtml('<div><p>文本</p></div>');
    expect(a).toBe(b);
    expect(normalizeHtml('<p><strong>x</strong></p>'))
      .not.toBe(normalizeHtml('<p>x</p>'));
  });
  it('stripAttrs 剔除运行时属性', () => {
    expect(normalizeHtml('<img data-ue-id="1" src="/a.png">', { stripAttrs: ['data-ue-id'] }))
      .toBe('<img src="/a.png">');
  });
  it('自闭合与布尔属性规范化统一', () => {
    expect(normalizeHtml('<br/>')).toBe(normalizeHtml('<br>'));
  });
});
```

- [ ] **Step 2: 跑测试确认失败**（`pnpm vitest run packages/test-utils` → FAIL: Cannot find module）
